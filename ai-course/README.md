# AI from Scratch

A course of about 80 lessons, each with a 60-90 s 16:9 explainer video, a quiz and code problems. The plan is in `SYLLABUS.md`; `course.json` is the machine-readable outline.

## Standing approval
See `course.md` for the full brief. The user pre-approved lesson scripts for this course (2026-10-24): write each lesson's script and build it without waiting for sign-off. The rest of the pipeline in the root `CLAUDE.md` still applies (Sarvam voice, no music, Hyperframes).

## Voice
Sarvam `bulbul:v3`, speaker **Priya** from lesson 1.2 onwards (user's choice, 2026-10-24). Lesson 1.1 was recorded with Ratan and pins `"speaker": "ratan"` in its `narration.json`. The provisional-timing rate in `tools/voice.py` was measured on Ratan; re-measure it once a Priya lesson exists.

## Per-lesson layout
```
lessons/<id>/
  narration.json   timing.json   lesson.json (quiz + problems)
  audio/  build/
  hf/              # Hyperframes project, 1920x1080
```

## Tools (run from `ai-course/`)
- `python tools/tts.py lessons/<id> [s1 ...]`: Sarvam takes per scene (needs `SARVAM_API_KEY`; in cloud sessions the proxy injects it, so any placeholder value works).
- `python tools/voice.py lessons/<id>`: builds `timing.json` and `hf/assets/voice.wav` from the takes (or a provisional word-count estimate with a silent track), copies `vendor/` into `hf/assets/lib`, and syncs scene timings and approximate word cues (`tools/align.py`) into `hf/index.html`. In the composition, `cue('s2','arrow')` is when that word is spoken; anchor beats to words rather than scene fractions.
- `python tools/otio_build.py lessons/<id>`: OpenTimelineIO record in `build/<id>.otio` (needs `opentimelineio`).
- `python tools/build_site.py`: refreshes `site/data/` and copies mastered videos into `site/videos/`.
- `python tools/check_lesson.py lessons/<id>`: every solution passes its tests and every starter fails one.

`vendor/` holds GSAP 3.14.2 and KaTeX 0.16.11, because headless Chrome cannot reach CDNs from every environment.

## Building a lesson end to end
1. `python tools/tts.py lessons/<id>`, then `python tools/voice.py lessons/<id>`.
2. In `lessons/<id>/hf/`: `npx -y hyperframes@0.8.118 check`, `snapshot --at ...`, then `render --quality delivery -o ../build/raw.mp4`.
3. Master: `ffmpeg -i build/raw.mp4 -c:v copy -af loudnorm=I=-14:TP=-1.5:LRA=7 -c:a aac -b:a 192k -movflags +faststart build/<id>.mp4`.
4. `python tools/otio_build.py lessons/<id>`, `python tools/check_lesson.py lessons/<id>`, `python tools/build_site.py`.

## Course site (`site/`)
Static files, no build step: `index.html` lists modules and lessons with progress; `lesson.html?id=<id>` has the video, key ideas, quiz and code problems. Code runs in a Web Worker with Pyodide 0.26.4 (NumPy loaded on demand) and is stopped after 10 s, so an endless loop cannot freeze the page. Progress and code drafts live in the visitor's `localStorage`. Pyodide and CodeMirror load from jsDelivr and cdnjs; without CodeMirror the editor falls back to a plain textarea.

Preview locally with `cd site && python3 -m http.server`. `site/data/` is generated by `tools/build_site.py` and committed. `site/videos/` is not committed, because the repo ignores `*.mp4` and `*.jpg`. Before hosting (GitHub Pages or Vercel), run `build_site.py` and either deploy that folder directly or put the videos on a host and point `video` at it.
